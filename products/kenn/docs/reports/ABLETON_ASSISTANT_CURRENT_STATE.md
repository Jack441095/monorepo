## Working locally

The repository-owned analyzer accepts mono/stereo 16-bit and 24-bit PCM WAV and measures duration, sample rate, bit depth, sample peak, RMS, crest factor, clipping runs, silence percentage, DC offset, L/R balance, correlation, mono cancellation drop, mid/side energy, FFT peaks, bounded time-localized FFT windows, bandwidth, confidence, and band energy. The analyzer abstains from spectral interpretation on short or effectively silent input; localized windows are an audit aid, not a continuous STFT or source-separation claim.

The existing `mix-review/adapter.py` now attaches the KENN spectral result as `analysis.spectral_evidence` while preserving the established receipt contract.

Device-parameter execution now also runs through `LiveActionService`
with exact target identity, stale-state rejection, idempotency, exchange
telemetry, verified readback, and confirmed inverse receipts. One native EQ
Eight `Output` plus Compressor `Threshold`/`Ratio` parameters are
real-Live-qualified on the disposable set, including manual stale-change
rejection; broader device coverage remains open.

Confirmation signatures are process-bound even when a configured root secret
is present; pending mutation confirmations therefore become invalid on
companion restart rather than surviving against an in-memory proposal store.

`POST /api/audio-analysis` exposes the KENN-owned spectral result directly for
one uploaded WAV, and `/api/audio-analysis/compare` returns hash-bound measured
deltas for two comparable files. The supported track and transport HTTP aliases and
autonomous tools now share `LiveActionService`, with proposal binding,
single-use confirmation, stale-state rejection, idempotency, readback
verification, receipts, and fresh-confirmation undo. Unsupported direct
mutations return disabled/410 responses, and legacy AudioGen clip-loading
side effects no longer send direct OSC writes.

The legacy batch-device executor is retained only for explicit compatibility
tests; production service calls reject batch execution until it is migrated
through the shared boundary.

The intent layer returns action, track, device, parameter, value, relative/absolute semantics, unit, confidence, missing fields, ambiguity, and confirmation requirement. It does not execute a write.

The optional Live command LLM path has an explicit `KENN_LIVE_LLM_MODE=shadow`
mode. In shadow mode the configured local model returns a bounded JSON plan for
comparison only; the deterministic parser still owns the intent sent to the
proposal service. The model must include exact current Live identity and typed
values, or validation rejects it. This is an evaluation path, not an approval
to enable autonomous Live writes.

The command gateway now recognises vague EQ “setting/value” wording as an
explicit clarification case. For example, “change band 2 to the EQ Eight
setting of .99 track 4” performs no write and asks for a parameter such as
gain, frequency, or Q plus the exact A/B band side. Leading-decimal values
such as `.99` are accepted by the bounded parser.

The 2026-09-04 command-path upgrade separates fast topology/device identity
reads from the full mixer/transport inspector and reuses the initial
topology snapshot during one command. This reduces avoidable waiting while
preserving the full inspector contract for operations that need mixer or
transport values. It does not change the confirmation, stale-state,
readback, replay, or undo requirements.
