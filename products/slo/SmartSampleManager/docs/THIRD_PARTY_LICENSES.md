# Third-Party Dependency License Audit

Generated by checking each dependency's actual vendored `LICENSE`/`COPYING`
file (for CMake `FetchContent` dependencies, in `build/_deps/*-src/`) or its
package registry's reported license (for Homebrew and PyPI dependencies),
not from memory. Every license claim below was verified against a real file
or `brew info`/`pip show` output at audit time.

## The one that actually matters before shipping

**JUCE 8.0.2 is dual-licensed: AGPLv3 or a paid commercial JUCE license.**
There is no free-and-proprietary option. From JUCE's own `LICENSE.md`:

> The JUCE Framework modules are dual-licensed under the AGPLv3 and the
> commercial JUCE licence.

AGPLv3 requires that source code be made available to anyone who receives
the software *or interacts with it over a network* — fundamentally
incompatible with distributing Smart Sample Manager as closed-source
commercial software. **A commercial JUCE license must be purchased before
any commercial (non-source-available) distribution of this application.**
This is a business decision and a cost (JUCE's pricing is tiered by company
revenue/size — check current terms at juce.com), not something resolvable
in code. Flagging it here as the top blocker rather than a footnote.

JUCE itself vendors several dependencies, each separately licensed (Apache
2.0, BSD, zlib, MIT, ISC, ~old MIT for HarfBuzz) — none of these are
individually a problem; they're all permissive. The AGPLv3-vs-commercial
choice on JUCE itself is the only one that matters here.

**TagLib is LGPL**, which (unlike AGPL) is compatible with proprietary
software *as long as it's linked dynamically* (so a user could in principle
relink a different TagLib build) rather than statically. This build already
links it dynamically via Homebrew's `libtag.dylib` (see `find_library
(TAGLIB_LIBRARY ...)` in `CMakeLists.txt`) — correct for LGPL compliance,
but worth stating explicitly rather than assuming. If a future build
switches to static-linking TagLib for distribution packaging, that would
need re-checking against LGPL's static-linking terms (still generally
possible, but requires providing relinkable object files or dynamic linking
at a minimum).

## AI model (Models/panns_cnn10_embedding.onnx)

| Model | License | Training data | Verified via |
|---|---|---|---|
| PANNs Cnn10 (qiuqiangkong/audioset_tagging_cnn) | MIT (code) | AudioSet (Google), **CC BY 4.0** | Repo's `LICENSE.MIT`; AudioSet's own license page |

Replaces the previous `dummy_clap.onnx`, which was an **untrained**
placeholder with randomly-initialized weights (`generate_dummy_model.py`) --
every embedding it ever produced was meaningless. This is a real, trained
model with the cleanest commercial-use provenance of every audio-embedding
candidate evaluated (see `Models/README.md` for the full comparison against
LAION-CLAP and Microsoft CLAP, both of which carry real complications: CLAP's
training data has an unresolved Freesound commercial-use caveat directly
from LAION's own README, and MS-CLAP's weights are Ms-PL, not simple MIT,
requiring separate attribution-notice compliance). AudioSet's CC BY 4.0 is
explicit, Google-published, and imposes no commercial restriction --
the same dataset lineage Google's own Apache-2.0-licensed YAMNet uses in
products shipped commercially today.

Full verification (numerical export parity + acoustic-meaningfulness
checks, not just "the license is fine") documented in `Models/README.md`.

## What's NOT audited here

- Any dependencies JUCE itself vendors transitively for formats/platforms
  this project doesn't build (e.g. AAX, LV2, VST2, Oboe/Android) --
  irrelevant to what actually ships, not included above.
- Fonts, icons, or other non-code assets: the only original asset is
  `Resources/AppIcon-1024.png`, generated by this project, not third-party.
- A production licensing backend's *hosting platform* dependencies (once
  one exists) -- out of scope until that's built.

## Bottom line for commercial distribution

1. **Buy a commercial JUCE license before shipping.** This is the one
   actual blocker among everything audited here.
2. Everything else (umappp's ecosystem, dr_wav, hnswlib, ONNX Runtime,
   libsodium, sqlite3, PANNs Cnn10, the Python server deps) is permissively
   licensed (MIT/BSD/Apache/ISC/Public Domain/CC BY 4.0) with no commercial
   distribution restrictions.
3. TagLib (LGPL) is fine as currently used (dynamic linking) but don't
   switch to static linking it without re-checking LGPL compliance.
4. If semantic text search (LAION-CLAP or MS-CLAP) is added later, that's a
   separate licensing decision with real tradeoffs -- don't assume it
   inherits PANNs' clean provenance.
