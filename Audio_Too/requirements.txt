# NumPy version is a TIGHT constraint, do not loosen — there is exactly one window
# that satisfies both sides on Intel macOS:
#   - LOWER bound >=2.0: the realtime player uses np.asarray(..., copy=True), a
#     NumPy 2.0+ API (crashes on 1.x with "asarray() got an unexpected keyword
#     argument 'copy'").
#   - UPPER bound <2.1 on x86_64: numba 0.60.0 (the last Intel macOS wheel) only
#     supports NumPy<=2.0. With NumPy 2.1+ numba FAILS TO IMPORT and ALL of
#     AudioGen's DSP (master_bus/mixer/reverb/sampler) silently falls back to pure
#     Python — ~100x slower render (7-15s/bar), which manifests as NO AUDIO in the
#     realtime player. This is not theoretical: an unpinned upgrade to NumPy 2.5
#     caused exactly that (2026-07-04). Keep NumPy on the 2.0.x line here.
# Apple Silicon (arm64) uses numba>=0.61 (see studio/audiogen/audiogen/pyproject.toml),
# which supports newer NumPy, so it is not capped.
# Torch 2.2 (final Intel macOS wheel) is ABI-incompatible with NumPy 2.x and prints a
# harmless import warning; KENN retrieval uses the torch-free ONNX embedder instead.
numpy>=2.0.0,<2.1; platform_machine == "x86_64"
numpy>=2.0.0,<3; platform_machine != "x86_64"
# numba/llvmlite pinned to the last Intel-macOS-compatible pair so DSP stays JIT-fast.
