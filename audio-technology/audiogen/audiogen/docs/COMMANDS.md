# Commands

This project’s realtime runner (`main.py`) supports interactive commands while audio is playing.

## Run

Start the realtime player (starts in **neutral**):

```bash
python3 main.py
```

With presets / overrides:

```bash
python3 main.py --preset <meta_preset_name>
python3 main.py --style <style_profile_name>
python3 main.py --style-architecture <style_architecture_name>
python3 main.py --pack <sample_pack_name>
python3 main.py --fx <fx_preset_name>
python3 main.py --arrangement <arrangement_mode>
python3 main.py --producer-macro <cinematic|club|intimate|narrative> --producer-macro-amount 0.8
python3 main.py --narrative-macro --narrative-macro-amount 0.9
python3 main.py --offline-export-dir songs --offline-export-prefix my_song
```

Offline mode now renders and saves audio by default:
- `<prefix>_<timestamp>.wav`
- `<prefix>_<timestamp>.mid`
- `<prefix>_<timestamp>.json` (song report)
- `<prefix>_<timestamp>.meta.json`

Default export folder is repo-local `/songs` (i.e. `<repo>/songs`).

Offline training runs from `main.py` too. Each run writes into a tagged folder
under `.cache/offline_training/<tag>/` by default and exits before audio startup.

One-command training pipeline (versioned artifacts under `artifacts/`):

```bash
python3 scripts/run_training_pipeline.py --version v001 --train all --dedup --require-metadata
```

Mixer DSP performance gate:

```bash
scripts/run_mixer_dsp_gate.sh
```

This writes `.cache/mixer_dsp_gate.json` and exits nonzero if mixer channel
strip performance regresses beyond the configured thresholds. Override defaults
with env vars such as `MIXER_DSP_GATE_MAX_MEAN_MS=1.2`.

Master bus DSP performance gate:

```bash
scripts/run_master_bus_dsp_gate.sh
```

This writes `.cache/master_bus_dsp_gate.json` and covers return FX, master EQ,
limiter, soft clip, and realtime/offline master-bus modes.

Generate a full training JSONL offline (no realtime playback/audio):

```bash
python3 scripts/generate_live_melody_training_jsonl.py \
  --out artifacts/datasets/live_melody/v001/live_melody_training.jsonl \
  --per-emotion 64 \
  --bars 16 \
  --role-cycle-length 6 \
  --quality-mode
```

Train a grouped melody Markov bundle:

```bash
python3 main.py --offline-train markov \
  --offline-train-jsonl artifacts/datasets/live_melody/v001/live_melody_training.jsonl \
  --offline-train-tag v001_markov \
  --offline-train-dir artifacts/runs/offline_training/v001_markov \
  --offline-train-grouped both \
  --offline-train-min-group-melodies 8 \
  --offline-train-dedup
```

Train the interval logit residual:

```bash
python3 main.py --offline-train logit \
  --offline-train-jsonl artifacts/datasets/live_melody/v001/live_melody_training.jsonl \
  --offline-train-tag v001_logit \
  --offline-train-dir artifacts/runs/offline_training/v001_logit
```

Run all offline training/export jobs with stricter metadata gates:

```bash
python3 main.py --offline-train all \
  --offline-train-jsonl artifacts/datasets/live_melody/v001/live_melody_training.jsonl \
  --offline-train-tag v001 \
  --offline-train-dir artifacts/runs/offline_training/v001 \
  --offline-train-require-metadata \
  --offline-train-min-emotions 4 \
  --offline-train-min-section-roles 3 \
  --offline-train-max-emotion-share 0.45
```

Outputs include a top-level `<tag>_offline_training_manifest.json`, plus the
underlying model manifests generated by the training scripts.

Promote a completed run into the active local model folder:

```bash
python3 main.py --offline-promote-run artifacts/runs/offline_training/v001/v001 \
  --offline-promote-kind all \
  --offline-promote-dir training_data/active_models
```

Then launch with the promoted artifacts:

```bash
python3 main.py --melody-retrained-markov \
  --melody-retrained-markov-path training_data/active_models/melody_markov.pkl \
  --melody-neural-logit-residual \
  --melody-neural-logit-residual-path training_data/active_models/melody_logit_residual.npz
```

Export and validate the structured emotion dataset (created on disk by export; not checked in):

```bash
python3 scripts/export_emotion_dataset.py --out-dir data/datasets/emotions/v1
python3 scripts/validate_emotion_dataset.py data/datasets/emotions/v1 \
  --report data/datasets/emotions/v1/validation_report.json
```

List/discovery helpers (print and exit without starting playback):

```bash
python3 main.py --list-preset-families
python3 main.py --list-meta-presets
python3 main.py --list-packs
python3 main.py --list-styles
python3 main.py --list-style-architectures
python3 main.py --list-fx
python3 main.py --list-arrangements
python3 main.py --list-producer-macros
```

Arrangement modes include `anthem` (longform cinematic-pop narrative arc).

## Interactive CLI (type while running)

You can type these into the same terminal session while `main.py` is running.

### List / apply meta presets (return FX moods)

List available meta presets (from `.audiogen/presets/`):

```bash
presets
```

Apply a meta preset (updates returns/macros immediately):

```bash
preset dreamy
preset ambient
preset grit
preset default
```

Supported macro keys (0..1) in meta presets (`.audiogen/presets/*.json`):
- `tempo`
- `swing`
- `melodic_intensity`
- `motif_familiarity`
- `lead_feel`
- `hook_strength`
- `hook_development` (higher = evolve hook faster across looped sections)
- `counter_melody`
- `harmony_development`
- `selection_quality`
- FX: `space`, `width`, `grit`

### List emotions

Print all available emotion profiles:

```bash
list
```

### Change emotion

Set emotion by **name**:

```bash
e joy
```

Set emotion by **index** (based on the `list` ordering):

```bash
e 3
```

### Random emotion

Pick a random emotion (tries to avoid repeating the current one):

```bash
n
```

### Change root

Queue a root change (keeps current emotion, changes root MIDI note):

```bash
root 64
```

### Stats

Print runtime stats:

```bash
stats
```

### Dialogue and melody Markov controls

Jam-oriented **arp↔melody dialogue** and optional **melody Markov** toggles (see `CompositionConfiguration` in `core/composition_config.py` for fields such as `melody_interval_duration_coupling_*`, `melody_breath_rest_bias_*`, `dialogue_amount`, and related flags).

Show current dialogue amount, preset, and melody feature flags:

```bash
dialogue
melody
melody show
```

Set overall dialogue strength (0..1) and reapply the dialogue macro (derived coupling flags):

```bash
dialogue 0.65
```

Use a coarse preset ladder (or clear the preset string):

```bash
dialogue preset off
dialogue preset tight
dialogue preset strong
dialogue preset experimental
dialogue preset clear
```

Toggle melody Markov upgrades (optional fourth argument sets strength 0..1):

```bash
melody pos on 0.8
melody rpc off
melody vl on
```

Runtime self-training model load:

```bash
python3 main.py --melody-retrained-markov
python3 main.py --melody-retrained-markov --melody-retrained-markov-path training_data/active_models/melody_markov.pkl
python3 main.py --melody-retrained-markov --melody-retrained-markov-hot-reload
python3 main.py --melody-retrained-markov --melody-retrained-markov-hot-reload --melody-retrained-markov-hot-reload-interval 1.0
```

### Help / quit

```bash
help
q
```

## Development

Install the project in editable mode so imports work without `PYTHONPATH` hacks (recommended for running `scripts/` and `tools/`):

```bash
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Run tests:

```bash
pytest
```

If you prefer not to install, use `PYTHONPATH=.` from the repo root (tests use `tests/conftest.py` to add the root as well).

**Scripts vs tools:** `scripts/` holds training and JSONL retrain pipelines; `tools/` holds offline metrics and analysis CLIs.

## Local sample WAVs

Sample packs live under `samples/` and are gitignored. See [docs/SAMPLES.md](SAMPLES.md) for layout, scaffolding, and which commands need WAVs on disk.

## Song quality audit (composition, no WAVs)

Generate arranged songs and score musical-quality signals (density, repetition, phrase boundaries, evaluation checks):

```bash
scripts/run_song_quality_audit.sh

# Gate on minimum score (exit 1 if any case fails)
SONG_QA_FAIL_UNDER=60 scripts/run_song_quality_audit.sh
```

Output goes to `artifacts/quality_audits/song_quality_audit_<timestamp>/` (untracked). See [artifacts/quality_audits/README.md](../artifacts/quality_audits/README.md).

Direct CLI:

```bash
python3 tools/song_quality_audit.py --performance low --fail-under-score 55
```

## Performance profiling

- **Startup stages:** set `AUDIOGEN_STARTUP_PROFILE=1` and run `python main.py` to print cold-start milestones (argparse → sampler rebuild → `CompositionGenerator` → audio container/player boot) from [`utils/startup_profiler.py`](utils/startup_profiler.py).
- **Realtime buffer / generation snapshot (no TTY):** `AUDIOGEN_STARTUP_PROFILE=1 python tools/rt_playback_health_check.py` prints stage timings on stderr and JSON on stdout (`buffer_underruns`, `callback_underflows`, `last_gen_time_ms`, `quality_tier`, etc.). Save the JSON and diff across commits.
- **Realtime performance gate:** `scripts/run_rt_performance_gate.sh` runs the low-mode live-path benchmark and fails when profiled bars exceed the realtime budget:

```bash
scripts/run_rt_performance_gate.sh
```

Tune thresholds with environment variables:

```bash
RT_GATE_SECONDS=12 \
RT_GATE_WARMUP_PROFILED_BARS=1 \
RT_GATE_MAX_RENDER_RATIO=0.85 \
RT_GATE_MAX_OVER_BUDGET_BARS=0 \
scripts/run_rt_performance_gate.sh
```
- **Realtime benchmark details:** `python tools/benchmark_realtime_audio.py --seconds 8 --performance low --output .cache/rt_benchmark.json` writes `stage_samples`, `stage_summary`, `stage_gate_summary`, `sampler_cache`, and `cold_start` fields so slow bars can be attributed to `mono`, `chords`, `mix`, or `master`. The gate can ignore cold-cache bars with `--gate-warmup-bars`.
- **Whole-system performance benchmark (offline + realtime):** `scripts/run_system_performance_benchmark.sh` runs offline composition timing plus the realtime benchmark and writes a single JSON report under `.cache/system_performance_benchmark/`. Tune thresholds with `SYS_BENCH_*` env vars:

```bash
SYS_BENCH_RT_SECONDS=8 \
SYS_BENCH_PERFORMANCE=low \
SYS_BENCH_MAX_RENDER_RATIO=0.85 \
SYS_BENCH_MAX_OVER_BUDGET_BARS=0 \
SYS_BENCH_MAX_UNDERRUNS=0 \
scripts/run_system_performance_benchmark.sh
```
- **Regression tests:** `pytest tests/test_rt_performance_health.py` checks telemetry schema, underrun accounting on an empty dequeue, and loose smoke bounds on `player.get_stats()` after a short run.
- **Realtime tradeoffs:** [`core/config_performance.py`](core/config_performance.py) applies named modes (`high`, `low`) via `CONFIG.set_performance_mode(...)` (see `main.py` defaults). Legacy names (`quality`, `balanced`, `maximum`) are still accepted for compatibility. Adjust these before micro-optimizing hot loops.
- **Hot paths:** after measuring (e.g. `cProfile`), focus on [`sampler/sampler.py`](sampler/sampler.py) and [`audio/engine/mixer.py`](audio/engine/mixer.py) only where profiles show cost.
- **Per-bar prepare vs render:** `AUDIOGEN_RT_BAR_LOG=1 python3 main.py` prints millisecond splits for `SectionScheduler.prepare_next_bar` versus `AudioRenderer.render_bar` (and total bar time) via [`utils/rt_bar_profiler.py`](utils/rt_bar_profiler.py).
- **Slow-bar cProfile:** `AUDIOGEN_RT_CPROFILE=1` profiles each generated bar; when wall time exceeds `AUDIOGEN_RT_PROFILE_SLOW_RATIO` times one bar duration (default `0.85`), logs the top `AUDIOGEN_RT_CPROFILE_TOPN` cumulative functions (default `25`). Use together with `AUDIOGEN_RT_PROFILE=1` (per-channel render breakdown in [`audio/RT_player/renderer.py`](audio/RT_player/renderer.py)) to see whether composition, slicing, or rendering dominates.

**Time-to-first-sound after picking a startup emotion:** the player runs a short synchronous preview (`CONFIG.audio.cold_start_preview_bars`, default 1 bar). If you hear buffer underruns right at cold start, try `2`. In arranged mode, `CONFIG.composition.arranged_emotion_switch_preview_sections` (default 1) controls the arranged cold preview size.

**Mid-play emotion changes** wait for phrase alignment (`CONFIG.audio.emotion_transition_boundary_bars`, default 4). Lower values (e.g. 2) switch faster but can sound less smooth.
