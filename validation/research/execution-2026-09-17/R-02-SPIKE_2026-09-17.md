# R-02 SPIKE RESULT — non-WAV discovery without new dependencies (2026-09-17)

Finding: the scanner decodes via dr_wav only (`SampleManagerEngine.cpp:25`,
CMake pin is the wav-specific dr_libs tag). No MP3/AIFF/FLAC decoder is
vendored, and TagLib (present, brew-unpinned) reads *metadata*, not audio.

Recommendation (no code changed — slo tree dirty; spike only):
use JUCE's built-in `AudioFormatReader` (WAV/AIFF/FLAC/MP3 on macOS desktop)
behind the existing WAV path as fallback. Rationale: JUCE is already a hard
dependency (8.0.2, and its commercial licence is the G-01 purchase anyway),
so this adds ZERO new licence surface, versus minimp3/dr_flac vendoring
which each add a component to the R-11 register. Effort M (2-3 wks incl.
parity fuzz vs WAV baseline); gated on R-01 passing first (don't widen
formats on an unproven classifier); kill if scan throughput drops >20% vs
WAV or any journal regression (same kill criteria as research plan).
